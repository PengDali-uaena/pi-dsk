# pi-dsk M0+M1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 做出一个能真正跑起来的 Pi 桌面客户端：窗口三栏、能发消息、能流式看到 assistant 文本 / reasoning / 工具卡片，能中断，能切模型与 thinking 级别。

**Architecture:** Electron 主进程持有唯一一个 `pi --mode rpc` 子进程，负责 JSONL 分帧、命令 id 关联、事件转发；preload 用 contextBridge 暴露白名单通道；renderer 是纯 React + zustand，只吃事件、只发命令，不碰 Node。

**Tech Stack:** Electron 33、electron-vite、React 19、TypeScript、zustand、react-markdown + remark-gfm、vitest。

设计依据：[2026-10-29-pi-desktop-gui-design.md](../specs/2026-10-29-pi-desktop-gui-design.md)

## 与设计稿的偏差（已确认）

设计稿写的是 `electron/` + `src/renderer/`，实际采用 electron-vite 的约定目录 `src/main`、`src/preload`、`src/renderer/src`，少写一层构建胶水。其余（单窗口单子进程、会话列表直读 jsonl、终端独立 node-pty）不变，后两项属 M2。

## 文件结构

```
~/pi-dsk/
├─ electron.vite.config.ts       # main / preload / renderer 三段构建
├─ package.json
├─ tsconfig.json + tsconfig.node.json + tsconfig.web.json
├─ src/
│  ├─ shared/
│  │  ├─ protocol.ts             # RPC 命令联合类型、IPC 通道常量
│  │  └─ chat-reducer.ts         # 事件流 → 消息列表（纯函数，可单测）
│  ├─ main/
│  │  ├─ index.ts                # app 生命周期、窗口、菜单
│  │  ├─ jsonl.ts                # 字节流按 LF 切帧
│  │  ├─ pi-manager.ts           # spawn / 写命令 / 读事件 / 关联 response
│  │  └─ ipc.ts                  # ipcMain 通道注册
│  ├─ preload/index.ts           # contextBridge: window.pi
│  └─ renderer/src/
│     ├─ main.tsx, index.html
│     ├─ app/AppFrame.tsx        # 三栏骨架
│     ├─ store/session.ts        # zustand：消息、运行态、模型、队列
│     ├─ features/composer/      # 输入框、发送/停止、模型与 thinking 选择
│     ├─ features/chat/          # 消息列表、文本块、reasoning、工具卡片
│     └─ styles/app.css
└─ tests/                        # vitest 单测
```
